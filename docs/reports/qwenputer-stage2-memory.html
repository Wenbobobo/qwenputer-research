PARAMETRIC MEMORY · CONTINUAL LEARNING

权重里的文件系统，
是更好的"记忆"吗？

Qwenputer 的文件系统把内容存进 Gated DeltaNet 状态，2–3 个 trace token 就能按名字精确读回，快照可跨会话。 它看起来像"比 RAG / 知识图谱 / Engram 更高效的记忆"。本报告拆开这个说法：它对，但只在很窄的窗口里对， 而且它根本不是"记忆"——它是一块内存映射的可编程外设。

01问题：记忆的三种幻想

"让模型记住"有四种完全不同的工程路线，它们经常被混为一谈。

幻想一 · "上下文足够长"

长上下文能记住原文，但读取不精确（100k 时 needle 37/50），更新冲突（新旧并存），且每轮都要付 KV 成本。

幻想二 · "编辑权重 = 写入记忆"

ROME/MEMIT 能改单条事实，但编辑互相干扰、不可枚举、不可撤销；上千条之后就不可控。

幻想三 · "查表 = 记忆"

Engram / Memory Layers 把知识存成可训练查找表：读便宜、容量大，但只在训练时写、推理时不可写、不可审计。

本工作给的"第四个选项"

把精确、可写、可寻址、可快照的 KV 存储做进推理时状态——代价是容量小、要编译器、要模型主动调用。

判断一个"记忆系统"要看七个维度：容量、写入成本、读取延迟、精确性、更新/遗忘、可审计性、可移植性。 任何只吹其中一个维度的方案都值得怀疑。

02定位：它是"可编程外设"，不是联想记忆

这是整份报告最重要的判断。把 Qwenputer FS 叫"参数化记忆"会误导：参数（编译出来的权重）定义的是接口，内容住在状态里。

类型代表内容在哪何时写精确性可审计
上下文 / KV长上下文模型注意力缓存推理时追加原文在场、读取近似高
外部检索RAG / 向量库 / KG / MemGPT外部索引推理时增删文本精确、召回近似高
参数化编辑ROME / MEMITMLP 权重离线求解概率性、互相干扰低
条件记忆Memory Layers / Engram可训练查找表只在训练时概率性（嵌入）低
循环状态DeltaNet / Mamba / Titans状态矩阵每 token 更新默认近似、会衰减低
编译式Qwenputer FSGDN 状态行推理时 2–3 token逐 token 精确高
换个说法：它像一块"内存映射设备"——按名字精确寻址、有协议、会满、会耗尽名字、不泛化、可快照、可逐行解码。 把它当"记忆"会高估它的泛化能力；把它当"外设"才能正确评估它的价值。

04成本模型：它只在很窄的窗口里更省

把一次"读查询"的代价按基座前向 E≈2N 归一化，可以得到一个可以证伪的比较。

方案每次查询成本1k 事实10k 事实100k 事实
RAG（检索+粘贴 k=5×100 token）C≈530 E；召回随 F 下降≈530 E≈530 E（需重排）≈530 E + 检索

Engram≈0 额外 token（<3% 吞吐）训练后 ≈0；推理不可写同左同左
它赢的四个条件（必须同时满足）：① ≤512 文件（约 2k 条短事实）；② 键名可约定、不需要 list；③ 执行端稀疏/压缩（τ≈1）；④ 跨会话且不允许外部服务。 此时一次查询 ≈50–80 token，RAG ≈530 token，快 6–10 倍且回读精确。
它输的场景：① 需要 list/语义检索（约 120 个名字以上 list 就超过 RAG）；② τ≈2.6 时合并税摊到每个 token；③ 事实数上万装不下；④ 语义查询（没有向量检索）。

0590 vs 30 的统计打假

作者的多会话基准：变更事实上 store 27/30（90%）vs 粘贴上下文 9/30（30%）。这看起来是"介质"的胜利。但：

  • 与同语义的主机 Python 工具相比：27/30 vs 25/30，Fisher 双侧 p≈0.71；全部题 75/90 vs 71/90，p≈0.57——没有显著差异。
  • 拉高收益的是覆盖式 put + 提示词 nudge；30% 的基线是"直接粘贴、无时间戳"，给了时间戳后上下文能到 75%。
  • 普通事实题上，粘贴上下文 60/60 明显好于 store 的 48/60（p≈3e-4）。
  • 数据是合成的、单 seed、30 道变更题；两个工具条件跑在不同 GPU 上；判分是大小写不敏感子串匹配。
结论："90 vs 30"证明的是覆盖式工具记忆 > 直接粘贴上下文，没有证明"权重内介质本身更优"。 要证明后者，需要 H1（时间戳/append-only 消融）与 H5（LongMemEval 语义查询对照）。
H1 补充实验（Stage 4，seed 0，n=30；见阶段四报告）：我们真的做了这个消融。给上下文加时间戳 + "以最新为准"后，严格评分（旧值不得出现）只到 12/30（40%），但放宽为"新值先于旧值"后是 30/30（100%）；作者基线（普通上下文）strict 9/30、lenient 18/30。 逐条看，strict 漏判全部是模型先给新值、再把旧值作为历史提一句。也就是说：30% 这个数字至少部分是评分器/回答长度的产物，不完全是"上下文不会更新"。 这给"90 vs 30"增加了第二个混淆项（评分方式与回答风格）。
覆盖语义对照（已完成 seed 0）：同为主机工具，覆盖式 C4 27/30=90%，append-only C2 只有 7/30=23%（与上下文 30% 同档）。
更关键的是 brevity 变体（pooled seeds）：同一份普通上下文只加一句"Answer in one short sentence."，更新题从 pooled 14/90=15.6% 直接变成 56/60=93.3%（C3s）；时间戳版 82/82=100%（C1s）。 结合 C4 是纯 Python 主机工具（无 in-weights 介质）也拿 90%，可以下结论：90 vs 30 的绝大部分差距来自回答格式/评分方式，而非记忆介质；覆盖语义只在"用工具"时起作用。

06与 Engram / RAG 的分工

Engram：训练时的静态知识

哈希 n-gram 条件记忆，O(1) 查表、容量到 100B 参数级、推理时不可写。优化"世界知识"。

Qwenputer FS：推理时的精确状态

按名寻址、覆盖式更新、快照持久、逐位精确。优化"用户/任务状态"。

两者正交，不是竞争：一个解决"模型知道什么"，一个解决"模型此刻记着什么"。理想架构是 Engram 做常识 + 编译式 store 做情景缓冲， 再定期用稀疏记忆微调把高频情景巩固进记忆层（类似海马–新皮层分工，这是假设）。

维度RAG / 向量库 / KGQwenputer FS
容量10^6–10^9 块512 文件 / 53k token
读延迟检索 10–100ms + 粘贴2–3 chip token + 逐字打印（5–6s 实测）
精确性召回归一化近似；文本精确按名精确；无语义检索
可审计/可移植高 / 高（外部系统）高 / 低（快照绑定编译与 hash seed）
依赖外部服务/编码器模型权重 + 驱动；无外部运行时

07持续学习：四层判定

层内容今天说明
(a)把事实写进状态、跨会话读回✅ 已实现新会话 50/50、200 条 100%；但保存率 78%、名字会耗尽
(b)把程序/固件编译进权重✅ 原型离线重编译+merge（4 min、峰值 44.7GB RAM）；改 checkpoint，不是运行时学习
(c)编译器生产新能力（无需训练）🟡 1–2 年需要 DSL/ISA/验证/资源预算/回归自动化；能力边界仍由人工原语决定
(d)元学习自动生成电路❌ 研究从自然语言规格综合可验证电路 + 保证 bf16/kernel 不变量，近期近似幻想
编译式写入的独特价值 = 零干扰：新电路占独立残差槽与 heads，Qwen 权重不动，KL 落在噪声底内。 对照：稀疏记忆微调学同样多新知识 NQ F1 掉 11%，LoRA 掉 71%，全量微调掉 89%（arXiv:2510.15103）。 这是"加知识"的一个严格上界参照。
真正的瓶颈不是存储，而是决策：保存率 78%、长对话里几乎不调用工具、工具定义在 100k token 前被"忘记"。 这只能靠学习/后训练解决（RL 目标：何时写、何时读），是比"把存储做大"更值得投入的方向。

08原创新实验（H2 / H3）

为了不让结论停留在文献里，我们在本机跑了两个纯 CPU 实验（脚本在 analysis/experiments/，原始数据在 h2h3_results.json）。

H2 · 名字键的别名与探测成本

用 Qwen tokenizer 编码 2000 个真实风格名字（snake_case、短名 s1..s200、前缀对抗名），测 6-token+长度键的别名率、线性探测命中/未命中的探测数、以及 get 的期望 chip token。

结果（2000 个名字，Qwen tokenizer 实测）：
· 真实风格名前缀：snake_case 770 个 0% 别名；短名 s1..s200 0% 别名；
· 对抗性同前缀名 400 个：100% 别名（前 6 token + 长度相同，符合协议定义）；
· 基准里 Qwen 实际生成的 630 个短名：0 别名，平均 2.19 token/名；
· 命中时平均探测数 2.05–2.49（负载 0.1–0.5），与线性探测解析值 ½(1+1/(1−α))≈2.17 吻合；
· 512 个 distinct-key 后耗尽：50 次试验平均 512 创建 / 1138 被拒 / 350 次别名覆盖。

H3 · list/get 与 RAG 的 token 交叉点

用 tokenizer 精确统计 list(n) 与 get(name) 的完整工具调用/响应 token，与 RAG（k=5×100 token 粘贴）比较，求交叉点 n*。

结果（tokenizer 精确计数，RAG = k5×c100 + 20 token 问题 ≈ 520 token）：
· get("user_city")：调用 24 token（含 2 token 名字）+ 响应包装 11 token ⇒ 10-token 内容的 get 总开销 45 token；chip 侧 ~2.05 token；
· list()：调用 12 token + 响应包装 11 token + 每个名字打印 3.55 token；
· 交叉点 n*：list+get(L10)=128，L20=125，L40=119，list-only=141 —— 与解析式 124.5、文档预测 100–150 一致；
· 结论：n_names > ~120 后，list 遍历就比"RAG 粘 5 块"更贵。

8.3 容量账：状态里到底装了多少信息？

量数值说明
store 逻辑信息量1,104,896 bit = 134.9 KiB目录 1024×130 bit + 内容 512×8×234 bit + 链/长度/order（按 store.py 的数据结构计）
同样 512×104 token 的 UTF-8 文本157 KiB（3.02 B/token 实测）信息密度比 ≈ 1.16×：状态存储几乎"不失真"
同样 53,248 token 的 KV cache1.625 GiB32 KB/token（8 层全注意力 × 4 KV heads × 256 dim × 2B）→ 是 store 逻辑量的 12,633 倍
全部线性层的 GDN 递归状态（fp32）72 MiB固定大小，与上下文长度无关；这是"物理介质"成本
这张表解释了为什么它"看起来高效"又不完全高效：逻辑上它把 53k token 的文本压进 135 KiB 的可寻址状态（与文本同量级）， 远胜 KV；但物理上这份状态是 72 MiB 的稠密矩阵——介质本身比 payload 大 ~500 倍。压缩空间在执行端（稀疏/量化），不在协议。

8.4 本机端到端复现（发布 checkpoint，纯 CPU）

上面的 H2/H3 是协议级测量。我们也在 22.3GB 发布 checkpoint 上直接复现了跨会话记忆（Ryzen 5700X / 48GB RAM / 纯 CPU， torch 2.14.1+cpu，单 token ~4.7s）：

会话 1（put，204.6s，69 text + 3 chip tokens，0 mismatch）：
Qwen 自发写 <tool_call><function=put>locker_code…</function></tool_call>
编译电路在权重内回答 ok；Qwen："I've saved your locker code as 4471-AZ."
→ 快照 store.npz = 11.5 KB（只存被写过的 state 行）

会话 2（空上下文，加载快照，170.4s，54 text + 2 chip tokens，0 mismatch）：
Qwen 自发写 <function=get>locker_code</function>
电路打印 4471-AZ；Qwen："Your locker code is 4471-AZ."
为什么这条证据重要：它把"跨会话、空上下文、按名精确回读、逐字符正确"四件事同时坐实， 而且是在没有 GPU、没有外部工具服务器的普通 CPU 机器上——说明这条技术路线不依赖特殊硬件；同时也暴露了代价： 端到端每个 text token ~4.7s，一次 get 往返 170s（作者 L4 GPU 上是 5–6s）。

09结论：什么时候用哪种记忆

需求首选理由
大规模世界知识 / 语义检索RAG / 向量库 / KG容量、模糊召回、可更新
训练时静态知识、极致推理效率Engram / Memory LayersO(1) 查表、容量大
少量、精确、跨会话的用户/任务状态Qwenputer FS（或同类精确 KV）按名精确、覆盖更新、快照、无外部依赖
需要精确计算 + 状态编译式协处理器（本工作）计算与存储同在前向内
要"泛化地记住"仍需 SGD / 稀疏记忆微调编译式写入不泛化
最终判断："in-weights 文件系统是更高效的参数化记忆"——过强。准确表述： 它是一个精确、零干扰、可审计的 KV 外设，在窄场景比 RAG 省 token，为参数化记忆研究提供了"精确写入"的上界参照。 它对"持续学习"的真实贡献是：证明了不遗忘的写入是可能的，并把瓶颈暴露在"何时写/读"的决策层。
