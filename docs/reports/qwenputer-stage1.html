01这是一台什么机器

先给结论：这不是"给模型加一个工具"，而是在模型内部造了一台真实的计算机， 而且是编译出来的——没有一行权重来自梯度训练。

普通语言模型做算术时，是在"猜"下一个 token。Qwenputer 不一样：当它写出一行 48213 × 9917 = 时，权重里的一颗 RISC-V CPU 真的开始执行乘法—— 它会先生成一串特殊的 trace token，这些 token 是 CPU 的执行日志； 然后它自己写出精确的答案。整个过程没有任何运行时、沙箱或工具服务器参与。

拆开看，它由四样东西组成

① 一个可精确寻址的 RAM

Gated DeltaNet 的状态矩阵，在 α=1、β=1、one-hot key 时退化成"精确覆盖一行"的 RAM。 Qwen3.5 自带 3/4 层这种线性注意力，所以不需要新层类型。

② 一个编译器

用 Python DSL 描述电路 → IR 图（FFN + attention head 节点）→ 逐层发射成 q/k/v 投影、 SwiGLU 单元、输出门。所有权重由编译器计算，无训练。

③ 一个 RISC-V 软核

RV32IM + Zba + 大数协处理器；256KB ROM / 128KB DROM / 32KB RAM 全部住在 GDN 状态里； trace token 驱动执行，1.2–1.4 token/指令。

④ 一个文件系统

1024 槽哈希目录 + 512 个 chunk（≈53k tokens）的链式文件；快照只占 ~30MB 状态， 跨会话持久；Qwen 用原生工具调用格式读写它。

为什么这件事值得认真对待：如果模型能在自己的权重里跑一个确定性的计算机， 那"精确性"就不必来自语言模型的概率近似——算术、协议、解析、状态机都可以是编译器生成的电路。 这也让"模型记忆"第一次可以是一个可寻址、可快照、可审计的文件系统，而不是一段模糊的向量。

02为什么 GDN 能做精确 RAM

这是整个项目的地基：一个线性 RNN 的状态，如何变成计算机的内存。关键在于三个参数的取值。

2.1 Delta 规则其实就是"按地址改写一行"

Gated DeltaNet 的每个 head 持有一个状态矩阵 S ∈ R^(dk×dv)（Qwen3.5-4B：128×128）。 每来一个 token，它做一次带门控的 delta 更新：

St = αt ⊙ St−1 + βt · kt ( vt − St−1T kt )T
α：遗忘门（0–1）· β：写入强度（0–1）· k：写地址（key）· v：写入值。读 = 用 query q 取 STq。

普通情况下 α、β 是学出来的、连续的，状态是"模糊的"关联记忆（Schlag et al. 2021 的 fast weights）。 把三个条件同时钉死：

条件取值结果
遗忘门 α1已写入的行永不衰减，可以永久保存
写入强度 β1旧值被完全替换，而不是混合
写 key kone-hot ej新值只落在第 j 行，其余行精确不变

代入公式：S ← S + ej(v − Sj)T，其中 Sj 是第 j 行 ——结果恰好是"第 j 行 ← v，其他行不动"。读也一样：q = ej 时 STq = Sj，精确读回。

一句话：当 α=1、β=1、key/query 都 one-hot 时，GDN 的状态矩阵就是一块"每行一个字节/字"的 RAM， 而且不随上下文长度增长——不像 attention 的 KV cache 越聊越大。

2.3 数字从哪里来：bf16 中的"精确"是怎么回事

语言模型的权重是 bf16（8 位有效位、8 位指数）。要让整台计算机在 bf16 里精确， 作者做了几件事（docs/q35.md）：

  • 所有中间值只用 8 位以内的有效位：位、one-hot nibble、≤256 的整数；12 位量拆成低字节+高 nibble。
  • SwiGLU 当精确 ReLU：取 K = 128，silu(128·x) 在电路产生的取值上严格等于 ReLU（x≤0 时恰好 0）。
  • Norm 隔离（ballast）：在 hidden 维里保留 m 个"压舱"维，每个 token 都填 B=240。 选 m 使 m·B²/hidden 是 4 的幂，于是 RMSNorm 对 chip token 的除数恰好是 sqrt(m/hidden)·B（2 的幂），余下的因子被折进权重——除法变成位操作，精确。
  • 常量用多个 bf16 拆开放进 ballast 维；matmul 在 fp32 累加，和是精确的。

一个容易忽略的细节：光"近似正确"不行。docs/q35-store.md 记录了 IR 求值器看不出来的两个 GPU 级 bug——norm 吸收（残差里的 226 会淹没 RMSNorm）和 slot 交接时的减法舍入。 这说明"精确"是逐 kernel、逐舍入挣来的，不是数学上的自动结论。

代价：这套精确性绑定在 bf16 + 特定 kernel 上。换成 fp16（比如 T10 这种不支持 bf16 的卡）会因为 240 的 ballast 直接溢出；换更快的融合 kernel 可能改变 chunk prefill 的 exp(cumsum) 舍入。这是它"脆"的地方，也是它暂时只能是研究原型的原因之一。

03编译器：把电路变成权重

没有训练，没有微调。整个"计算机"是一张图，编译器把图逐节点翻译成 transformer 层的权重。

3.1 三层抽象：DSL → IR → 权重

IR 里只有两类节点，它们正好对应 Qwen3.5 的两种 sublayer：

  • Head 节点 → 一个 DeltaNet 注意力 sublayer。q/k 是输入的线性投影行（可带 conv lag tap，用来读"上一个 token"的后验特征）； v 是写入值；β 通过 in_proj_b 的 sigmoid(256g−128) 给出恰好 0/1 的写门； α 通过 in_proj_a 给出 1 或 0（用于整 head 清零）；输出门 z 与 out_proj 决定读到哪些 IR 维。
  • FFN 节点 → 一个 SwiGLU MLP。每个单元计算 coef · silu(K·a) · b， 其中 a、b 是 IR 维的线性组合——这是"可编程的 AND/阈值"；输出对某个 IR 维做加性写入。

3.3 层里到底有什么：以 4B 为例

发布 checkpoint：hidden 4608（Qwen 原 2560 + chip 维），44 层 = 12 个 chip 层 + 32 个 Qwen 层， vocab 484,800（Qwen 的 + 236,469 个 trace token），tied embedding，22.3GB bf16。 每个 chip 层就是一个 DeltaNet sublayer（16 key heads / 32 value heads，head dim 128）加一个 MLP（9216 单元）。 电路本身只有约 0.78M 个非零权重——其余全是零填充。这也是 22.3GB 里"水分"的来源， 同时是第 10 节优化机会的入口。

展开：为什么"零填充"不可避免？（架构约束）

Qwen3.5 的 checkpoint 要求所有层同宽（hidden 4608）、MLP 同宽（9216）。chip 层的宽度由电路需要的 IR 维数 与 ballast 决定（pick_hidden 取 m·4k），而电路本身只用到其中一小部分。 另外 Qwen 自己的 32 层也被零填充到 4608（原 2560），vision tower 也被一起打包。 上游 q35-size.md 把这笔账算得很清楚：v15x 里 2944 宽的 chip 层 1.56B 参数中只有 0.8M 非零。

04RISC-V CPU 的电路布局

一颗完整的 RV32IM 软核，被拆成 11-12 个 transformer 层。内存不是"模拟"的，而是真正在状态矩阵里。

4.1 机器规格

部件规格住在哪里

RAM32 KB（.data / TLS / .bss / heap / 栈）32 个 DeltaNet key heads 的状态行
DROM128 KB 只读数据（.rodata）16 个 head / sublayer

4.2 执行日志 = token 流

每条指令被编码成一条"记录"，记录由 1-7 个 token 组成。token 家族本身就是字段： V（15 位值）、F0/F1（格式标签）、J/R（跳转/刷新）、 BYTE（putchar）、HALT。CPU 的状态只在一条记录的最后一个 token 处提交； 记录内部靠 conv lag tap 重组。这就是为什么 trace 不是"给模型看的文本"，而是电路真正的时序信号。

addi a0, a0, 5 → F0 · V F1 · V V F2 （值按符号扩展后的 15 位块数决定 1/2/3 个 token）
jal ra, func → J(16 位字偏移) （link = PC+4 在电路里算）
sw a1, 0(a2) → ST0/ST1 （地址 bit6 选 value head，数据是 rs2 的滞后 tap）
ecall → HALT

实测 1.0–1.55 token/指令（C 程序平均 1.40；MicroPython 1.24–1.26）。相比之下 CHIP-8 要 3–5 个 token/指令。

4.4 为什么是"精确"的（而不是"近似正确地算对"）

  • ROM 预解码：每条指令在加载时变成预解码字（uop | rd | rs1 | rs2 | imm），运行时只需查表 + 字段 one-hot。
  • 地址即 key：表的行地址由 2-bit one-hot 组拼出——"key 通道 = 各组之和 − (n−1)"，本行恰为 1，其余 ≤ 0。 于是 128 行 × 80 个 head 的表不需要 10,000 维 one-hot。
  • 写门是 sigmoid 的端点：sigmoid(256g−128) 在 g∈{0,1} 时精确等于 0/1，保证写入是"覆盖"而不是"混合"。
  • 加法/乘法是 2-3 级 MLP 的逐位构造：进位、部分积、除法比较都用阈值单元拼出，所有中间值都落在 bf16 可精确表示的范围。
验证规模：riscv-tests 的 rv32ui (38) / rv32um (8) / rv32uzba (3) 全绿； 61 个 ELF 与 qemu-riscv32 的 exit code / stdout 一致；C 程序（crc32、qsort、sieve、mini-gmp）与 MicroPython（s1/s5） 共 约 1800 万条指令自由运行（不与参考模型对齐、完全靠自己输出继续跑）零错误。

05桥：模型如何"看见"CPU

最反直觉的一点：Qwen 并不是"被告知"自己在用工具。它只是像平常一样写工具调用，而编译层在半路把执行结果写回来。

5.1 没有工具，只有 token

Qwen3.5 在预训练时见过大量工具调用格式（<tool_call><function=calc>...）。 Qwenputer 直接借用这个格式，但没有任何外部进程会截获它：

<tool_call><function=calc><parameter=expr>123456789*987654321</parameter></tool_call>
　　　　↓ chip 层在 </tool_call> 处接管（owner=1）
[trace tokens: 运行 RISC-V 固件]
\n<tool_response>\n121932631112635269\n</tool_response>\n
　　　　↓ Qwen 读到这个"工具返回值"，像普通文本一样继续

5.2 "任意 token 进，任意 token 出"

要让编译层读到 Qwen 写出的参数（数字、文件名、文本），每个 Qwen 词表行都被附加了两组 chip 维特征：

  • id bits（18 维，0/1）：这个 token 自己的 id 位。它是输入特征，所以电路"认识"任何文本 token——不只是数字。
  • id code（18 维，±κ）：输出码。要打印 token X 时，exit 层把 X 的 id 位以 ±κ 留在这些维里； lm_head 对 X 行的得分比其它 Qwen 行高出一截（4 倍 gain、8 个 class-code 单位的 margin），argmax 会精确选中它。

特殊 token（<|endoftext|> 及以后）的 id code 被清零，所以内置存储永远无法打印出 <|im_end|> / <|im_start|>——这是一条硬隔离。

5.3 让 Qwen "无感"：mute 与 tau

chip token 不能让 Qwen 的 32 层看到，否则文本行为会被污染。做法：

  • mute：在 chip 层对 chip token 位置把 Qwen 的 DeltaNet 门（a/b/z）和 attention 输出门压到 −1024， Qwen 的状态对这些位置"透明通过"；一个 anti-sink key 防止 chip 位置吸收 attention。
  • tau 与 owner：最终 norm 的 gain 对 tau 维给 260，于是"下一个 token 该由电路还是 Qwen 生成"是一个 赢面极大的 argmax 选择；文本 token 的 tau = 2−40，chip token 的 tau = 0。
  • exit：最后一个 chip MLP 把除 mu/tau/输出码以外的所有 chip 维清零并清掉 ballast， 让 Qwen 的层收到它"习惯的"输入。
结果：Qwen 的文本行为与 base 的 KL 只有 5.5e-4（噪声底 5.1e-4），greedy 文本 16 个 prompt 里 10 个逐 token 相同， MMLU/ARC 在噪声内。同时它在 50 轮"把这些存成 sK"的对话里 50/50 次自己调用了 put。

5.4 固件 = 编译后的软件

CPU 上跑的第一份"软件"是 calc 固件：一个 C 程序，支持 + − × / // % ** gcd() 与括号、小数、精确有理数（分数约分），值最长 62 位。 它被 gcc 编译成 RV32 的 ELF，加载到 ROM/DROM，启动时把快照注入 GDN state。 调用一次 calc 的成本：约 1.3k–3k trace tokens（L4 上约 0.5–1 秒）。

06文件系统：一个装在状态里的硬盘

CPU 之上再叠一层持久化：put / append / get / list / delete，存在 DeltaNet 状态里，可快照、跨会话。

6.1 目录：把文件名哈希到 1024 个槽

文件名取前 6 个 token（每个 18 位 id）+ 长度 3 位 = 111 位，经过一个固定随机 GF(2) 线性映射压成 10 位 （1024 个槽）。冲突用线性探测；删除留下墓碑（tombstone），只有同名可以复活。一张 order 表记录创建顺序， 所以 list 能按首次创建顺序列出。

6.2 存储布局：内容行"顺便"写入

写文件的内容不需要额外的 trace token：当 Qwen 正常写出 put(name, text) 的参数时， 每个文本 token 都在改写它对应的 content 行——一个 staging head 记住"当前 value head 的 7 个 token"， 行在写调用结束时自然包含全部内容（docs/rv-store.md 的 "Content rows"）。 这样存储是"免费"的，只有目录操作要花 trace token。

6.3 跨会话：快照就是记忆

持久表（目录、内容、链、len、order、寄存器）对应的 value heads 的 recurrence state， 在 4B 模型里是 169 个 value heads；上游文档给的满容量量级是 11MB（q35-store.md）、模型卡写 30MB（口径不同）。 本机实测：只存被写过的行——一个文件（locker code）的快照只有 11.5 KB，不是固定 11–30MB。 保存它为 memory.npz， 下次可以构造一个只填了这些 heads 的 DynamicCache：新会话的上下文是空的， 但里面的文件还在。模型卡里的两条命令就是全部魔法：

uv run python -m chipformer.rv.chat qwenputer-filesystem --memory memory.npz \
    --ask "Remember that my locker code is 4471-AZ."
uv run python -m chipformer.rv.chat qwenputer-filesystem --memory memory.npz \
    --ask "What's my locker code?"
本机实测（2026-10-29，纯 CPU，发布 checkpoint）：
会话 1（put）：Qwen 自发 put → 电路回 "ok" → "I've saved your locker code as 4471-AZ."（69 text + 3 chip tokens, 204.6s）

07前史：相似工作为何没有成功

把计算机塞进神经网络不是新想法。过去三十年里，它至少以四种面貌出现过——但每条路线都缺一块， 直到"可精确寻址的线性状态 + 编译式权重 + 预训练基座"三块拼图同时出现。

7.1 路线一：把记忆放进状态——数学很早就对了

  • Fast weights（Schmidhuber 1992）：慢网络用梯度"编程"快权重，快权重做临时记忆。概念正确，但没有精确性，也没有可寻址性。
  • 线性注意力（Katharopoulos et al. 2020, arXiv:2006.16236）：把 softmax 注意力写成核特征内积，于是注意力可以按 RNN 递推——状态成为固定大小的"记忆"，但它是加性外积，写多了会互相干扰。
  • Fast Weight Programmers（Schlag, Irie, Schmidhuber 2021, arXiv:2102.11174）：证明线性注意力等价于快权重程序员；提出用 delta 规则只替换一个方向、不扰动其它方向。这正是 Qwenputer 的数学地基。
  • DeltaNet（2024）→ Gated DeltaNet（2024, arXiv:2412.06464）：把"定向更新"和"门控遗忘"做进可并行训练的层。Qwen3.5 恰好大量使用 GDN（3/4 层），于是"模型自带 RAM"第一次成为工业级事实。
这条路线没失败在数学上，失败在目标上：所有这些工作都追求"学到有用的模糊记忆"， 没有人要求状态里的值可以被精确寻址、逐位验证。Schlag 2021 甚至明确说外积记忆容量有限、会干扰—— 而 Qwenputer 做的恰好是把这个"缺点"变成特性：只用一个方向（one-hot），把干扰降为零。

7.2 路线二：把程序编译进 Transformer——结构对了，但只在玩具里

  • Tracr（Lindner et al. 2023, arXiv:2301.05062）：把 RASP 程序编译成 decoder-only Transformer，用于可解释性研究。编译思想完全正确，但它生成的是新的小模型，不是往预训练模型里插电路，也没有 CPU 语义。
  • Looped Transformers（Giannou et al. 2023, arXiv:2301.13196）：固定层数循环使用来模拟计算块。依赖外部循环，不是单次前向。
  • In-context 梯度下降（von Oswald et al. 2022, arXiv:2212.07677）：构造权重让线性注意力执行梯度步——证明"权重可以编程出算法"，但只是一个算法，不是一台机器。
  • Program-as-Weights（Zhang et al. 2026, arXiv:2607.02512）：最接近的同行。一个 4B 编译器把自然语言规范变成 adapter，驱动冻结的 Qwen3-0.6B 解释器；摘要称效果接近直接 prompt Qwen3-32B，推理内存约 1/50。但它的编译器是训练出来的、输入是模糊规范、不承诺确定性。它解决"规范模糊时快速造函数"，Qwenputer 解决"精确计算如何嵌入模型"——两者互补。

7.3 路线三：参数化记忆——能写入，但不可操作

工作做法为什么没成为通用记忆
ROME / MEMIT（2022）定位中层 MLP 里的事实，做低秩编辑编辑会互相干扰；不可枚举、不可撤销、无审计；只适合少量事实
Memory Layers at Scale（Meta 2024, arXiv:2412.09764）可训练的稀疏 KV 查找，加参数不加 FLOPs映射是学出来的，只在分布内可靠；不是可寻址的符号存储
Titans（2025, arXiv:2501.00663）测试时用梯度步写入神经长期记忆写入的内容不是可验证的符号；遗忘/更新不可控
Engram（DeepSeek & PKU 2026, arXiv:2601.07372）哈希 n-gram 查找作为与 MoE 并列的条件记忆轴本质是"学出来的查表"，没有精确写出/读回语义；不是文件系统

共同缺口：写入的内容无法被精确地、逐位地读回来，也无法枚举、快照、审计。这正是"记忆"与"存储"的区别。

7.4 路线四：外部记忆——精确，但不在模型里

RAG（arXiv:2005.11401）、向量库、MemGPT（arXiv:2310.08560）、知识图谱解决的是"精确内容放在外面、需要时检索进上下文"。 它们成熟、可溯源，但代价是：每次都要把内容重新粘贴进上下文（token 成本、延迟）、依赖外部服务与沙箱、 并且模型本身仍然不能计算这些内容——只能阅读。Qwenputer 的文件系统第一次让"存储"与"计算"共处同一个前向。

7.6 什么是真正新的（谨慎结论）

组件都不新：快权重、delta 规则、门控、哈希表、RISC-V、编译式 Transformer 全都有几十年历史。 新的是组合与完成度：在预训练模型的现有 GDN 层里，用 α=1、β=1、one-hot 键做出精确寄存器堆， 用编译器把完整 RV32IM CPU 和文件系统写进权重，零训练、文本行为几乎不变、并通过 riscv-tests 与上亿条指令的自由运行验证。 据公开检索（覆盖有限），此前未见同类工作直接做到这些。

引用注意：仓库的"多会话召回"（90 题，83.3 vs 7.8）是作者自建的 LongMemEval 风格数据集， 不是官方的 LongMemEval（arXiv:2410.10813）；所有 benchmark 数字均为作者自测，本报告在复现前按"作者声明"标注。 仓库文档写 22.3GB、博客写 18.8GB——本机实测发布 checkpoint 为 20.73 GiB（≈22.3 GB 十进制），以实测为准。

08为什么这次可行

同样的想法在 2014 年的 NTM、2021 年的 fast weights、2023 年的 compiled transformers 里都出现过雏形。 为什么直到 2026 年、在一个 4B 的 Qwen 上才第一次"真的跑起来"？答案是五个条件同时到位。

条件一 · 架构上终于有"可精确寻址的状态"

Gated DeltaNet 把状态压缩成一个矩阵，且 α、β 是 per-head、per-token 的门——它们可以被权重精确地钉死在 0/1。 纯 softmax attention 的 KV cache 也能当内存，但它是"追加"而非"覆盖"，且随上下文增长；普通 RNN 的状态则总量固定但无法寻址。GDN 恰好两者兼得。

条件二 · bf16 的精确性刚好够用

电路只需要 8 位有效位（位、nibble、≤256 整数）。bf16 有 8 位有效位，且 2 的幂缩放让 norm 除法变成位操作。 作者实测了 GPU kernel（fla 的 chunk prefill 与 recurrent decode）在 bf16 下对这些受限取值逐维 bit-exact；fp32 反而不是 bit-exact 的。

条件三 · 自动化验证：IR 求值器

电路不是"训练完发现坏了"再修；它在 IR 层有一个逐 step、逐 bf16 舍入的精确求值器。 所有正确性先在这里和参考模拟器对齐（1M+ token），再上 GPU 复核残差。没有这一层，编译器规模根本不可维护。

条件四 · 基座可以"外科手术式"复用

Qwen 的权重一个都不改：只做零填充（保持归一化输入需乘 sqrt(D/D')）、把 chip 层插到前面、用 mute 让 Qwen 对 chip token 透明。 文本行为 KL 5.5e-4，几乎无损。作者不需要"重新训练一个模型"，只需要"给一个模型装外设"。

条件五 · 工具调用格式是现成的接口

Qwen3.5 在预训练中见过大量 <tool_call> 样本，它免费地会写工具调用、 会读 <tool_response>。作者不需要训练"如何使用计算机"，只需要让编译层在正确的位置接管 token。 50/50 次自发 put、16 个 prompt 里 10 个逐 token 相同——证明接口兼容得非常好。

反条件 · 什么让它仍然只是"研究原型"

强耦合：换基座版本、换 kernel、换 dtype 都要重做精确性论证；慢：每条指令 ≈ 1.2 个完整 forward； 大：11B 参数里只有 0.78M 非零；窄：只能做编译器预先描述过的操作。它不是通用答案，而是一个存在性证明。

8.3 它仍然只是原型的三个理由

  1. ABI 没有冻结：基座版本、kernel、tokenizer、chat template 全是发布 ABI 的一部分。
  2. 端到端并不更快：store 单题 5–6s vs host 工具 2.3s；多会话基准 79min vs 48min。收益是内聚性、精确性、无外部依赖，不是速度。
  3. "自我进化"还差得远：事实写入状态已实现；程序编译进权重需要人写 IR；自动生成新电路是研究问题；元学习合成无 bug 的 bf16 硬件电路近期接近幻想。

8.1 一个对照：为什么"训练"做不到这些

用梯度下降教一个 4B 模型做大数乘法，你得到的是概率上正确：97% 的题对，3% 的题错在最后几位。 而 Qwenputer 的 97.5% 分数里，每一个被 CPU 算出的结果都是精确的——错的是 Qwen 在拿到正确结果之后的后续文本 （重复调用、丢符号、不写最终答案）。这是"能力边界"与"样本分布"的根本区别：编译器生成的电路没有错误率，只有覆盖范围。

这也解释了为什么作者强调"no runtime / no tool"：精确性来自权重本身，而不是来自一个恰好可用的 Python 进程。 后者在真实部署里意味着延迟、故障域、供应链和安全边界；前者把这些都变成模型的一部分。

11记忆与持续学习：它比 RAG / Engram 更高效吗？

11.3 那个诱人的 90% vs 30%，要打折扣

作者的多会话结果里，store 版在被修改的事实上 27/30（90%），而"把旧会话粘进上下文"只有 9/30（30%）。 这看起来是"介质"的胜利，但拆开看：

  • 与同样语义的主机 Python 工具相比：27/30 vs 25/30（Fisher 双侧 p≈0.71），全部题 75/90 vs 71/90（p≈0.57）——没有显著差异。
  • 收益来自覆盖式 put + 提示词 nudge，而不是"写在权重里"。
  • 30% 的基线是"直接粘贴旧聊天、没有时间戳"；给了时间戳/覆盖语义之后，上下文能接近 75%。 而在普通事实上，粘贴上下文 60/60 明显好于 store 的 48/60（p≈3e-4）。
  • 数据是合成的、单 seed、每例 8 条事实、30 道变更题，两个工具条件还跑在不同 GPU 上。
结论："90 vs 30"证明的是覆盖式工具记忆 > 直接粘贴上下文，没有证明"权重内介质本身更优"。 要证明后者，需要 H1（时间戳上下文 / append-only 工具消融）与 H5（LongMemEval 语义查询对照）这类实验。

11.4 与 Engram 的关系：正交，不是竞争

Engram（DeepSeek & PKU 2026, arXiv:2601.07372）是训练时写入的哈希 n-gram 条件记忆：查询 O(1)、容量可以到 100B 参数级、 推理时完全不可写。Qwenputer FS 是推理时写入的精确寄存器堆：写入 2–3 token、容量只有 53k token、不可训练。 一个优化"静态世界知识的查表"，一个提供"任务/用户状态的精确工作区"——理想的架构可能是两者叠加： Engram 做常识，编译式 store 做情景缓冲。把它们放在一起比"谁更高效"是类别错误。

12.2 应用场景：它真正擅长什么

① 可验证的精确算术/符号计算

大数乘除、gcd、有理数、CRC、排序——凡是"必须 100% 正确、且可以被编译器描述"的计算。对金融、科学计算、密码学相关的 agent 极有吸引力。

② Agent 的持久记忆

文件系统 + 快照 = 跨会话、可寻址、可审计的记忆。相比 RAG 的"检索-粘贴"，它在模型内部完成读写，token 开销低（2–3 tokens/操作），且天然精确。

③ 安全与可监控性

作者的两个 follow-up 指向这里：混合模型可以把推理藏进 RNN 状态、绕过 CoT 监控；反过来，编译进权重的"监控器/答案密钥"是模型无法关掉的。这是一个全新的可解释性/安全工具面。

④ 可编程的模型能力

把排序、解析、协议状态机、正则匹配编译成电路，作为"专家外设"按需装载。模型不再只能"学"能力，还可以"安装"能力——这是第 3 阶段的探索方向。

⑤ 长上下文之外的记忆

1M token 上下文仍然有注意力成本；而 GDN 状态大小恒定。把"必须记住的少量精确事实"放进状态/文件系统，把"需要语义理解"的留给上下文，是一种混合架构。

⑥ 教学与研究基座

它是目前最好的"神经网络可解释性/可编程性"沙盒：每个电路都可比对参考模拟器，每个 token 都可验证。

12.3 风险与边界（必须说清）

  • 数值依赖：bf16 + 特定 kernel + 特定基座版本。升级任何一环都要重新证明精确性。
  • 规模税：11B 参数里 0.78M 非零，"装着计算机的模型"比"计算机"大五个数量级。
  • 能力窄：只能执行编译器预描述的操作；"任意程序"需要重新编译 + 合并模型。
  • 工具格式依赖：Qwen 自发使用工具调用的能力是前提；换一个不擅长 tool-call 的基座，桥就断了。
  • 记忆不是学习：写进文件系统的是数据，不是技能；真正的"自我进化"仍需要编译器生成新电路（见第 11 节）。
  • 安全边界：精确计算能力 + 不可监控状态，是双刃剑；作者已经把这一点作为下一步研究方向。
