# Stage 3 · 创意与原型（草案）

> 目标：在「复现 + 优化 + 研究」之后，给出 3–5 个可评估的创意，其中至少 1 个做出原型/实验证据。
> 原则：每条都给做法、预期收益、风险、验证方式、当前证据。

## 创意 A · 编译器即安装器（In-weights package manager）★★★

**想法**：既然 12 个 chip 层的权重全部由编译器确定性算出（1.29M 非零、~2.5MB 数据），
发布物可以只是「Qwen 基座 + 编译器 + 配方（seed/布局/槽位/anti-sink 列）」，首次加载时本地重建 chip 层。
进一步：不同'设备'（算法/固件/文件系统版本）就是可插拔的编译单元，'安装设备' = 重新编译 + 合并。

**为什么值得做**：
- 下载 22.2GB → 约 8GB（基座）+ ~130MB（delta，zlib 后 ~6MB）；chip 层部分趋近于零。
- 也是「发布权重 == 编译器输出」的**可审计性**证明：如果重建出的 chip 权重与发布 checkpoint 逐位一致，
  说明作者没有偷偷训练/修改 chip 层——这是整条技术线最关键的信任前提。

**原型（本机可做）**：analysis/rebuild/rebuild_chip.py
1. 读 chipformer.json（layout rv1-store、hidden 4608、slots/heads/dims）。
2. core.build(Target(...), Text(tokenizer), store.Config(...)) → allocate → Layout(hidden=4608, off=2560, m=18, slots)。
3. emit_layers(...) 发射 12 层权重；与 .data 中对应张量逐位比较（bit-exact）+ 统计零值模式。
4. 输出 analysis/rebuild/report.json + 中文报告。

**阻塞/风险**：anti-sink 列（8×1024 bf16，来自设备相关拟合）必须作为'配方'存储；rv-store 分支代码未锚定 commit；
不重建 Qwen 层（需要基座，本机未下载）；merge 全量峰值 44.7GB RAM，但只重建 chip 层约 4–6GB 即可。
**预期**：chip 层大部分逐位一致；若部分不一致，定位到 fit_anti_sink / 浮点发射顺序，也是重要发现。

## 创意 B · 每设备独立编译（Device tree）★★

**想法**：把 CPU 之外的算法（排序/CRC/正则/日期）编译成'外设'，按需合并；每个设备有自己的输入/输出 token 族与 ROM。
**可行性估算（来自 rv32.md）**：一个 RV32 核 = 11 层；专用组合电路（如 8 元素排序网络）可能 2–3 层、几千个非零权重。
**收益**：模型可'安装'能力而不训练；**风险**：每设备都要精确性论证 + 层预算；与 Qwen 的耦合面（mute/tau）要重复处理。
**验证**：用现有 IR 对一个小算法（如 CRC32 的位级实现）估算层数/head/units，与 calc 的 token 成本对比。

## 创意 C · 不可关闭的监控器（In-weight monitor）★

**想法**：作者 follow-up 声称把线性探针 + 标志日志编译进权重，捕获 91% 谎言、零误报。
**可复现性评估**：需要作者代码/权重/数据集（未发布完整版）；本机无 GPU 窗口做大规模评测。
**本机可做**：在 IR/小模型层面验证'探针电路'的可行性与边界（例如把某个隐藏维的线性阈值做成 chip token 输出），
并给出**证伪清单**：模型能否通过 tool 调用/桥接 tag 绕过监控？多模型/多提示下的 AUROC 是否稳定？
**判断**：概念有吸引力，但'不可关闭'的宣传需要覆盖证明而非 demo。

## 创意 D · 记忆盘（Memory disk / 快照可移植性）★★★

**想法**：store 快照 = 可存盘、可加载的'记忆盘'；文件跨会话持久。但快照绑定编译（hash seed、head 布局、tokenizer）。
**实验（IR 级，纯 CPU，1–2 分钟）**：
1. 参考 store 建 10 个文件 → 快照；
2. 新会话载入 → 读回 100%；
3. 改 hash seed/布局后再载入 → 预期读回 0%，证明'记忆不可跨模型迁移'；
4. 测量快照大小 vs 文件数/内容量（作者口径 11MB vs 30MB 的差异）。
**意义**：把'记忆可移植性'从宣传变成可测边界；也给出'记忆盘'产品的正确边界（同模型、同编译、可复制）。

## 创意 E · 自举 Qwenputer / in-weights Linux（思想实验，量级分析）★

**想法**：让模型内部的 CPU 运行编译器，自己生成自己的电路（自举）；或把 Linux 跑在权重里。
**量级**：RV32 核占 11 层、~1.04M 非零权重；ROM 256KB。Linux 内核 ~30MB 代码 → 需要 ~100× ROM → 数百层/数十亿非零权重，
远超当前 44 层/11B 参数的预算；且每层 token 成本线性增长。**结论**：自举/OS 级在近期的 transformer 里不可行，
但'把一个编译器的子集编译进权重、由模型自己调用生成新固件'是可行的中间形态。
**价值**：给出清晰的规模边界，避免'模型内计算机 = 通用计算机'的误解。
