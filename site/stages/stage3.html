01A · 编译器即安装器（In-weights package manager）最高优先级

发布物可以不是 22GB 权重，而是「基座 + 编译器 + 配方」；这也是"chip 层是算出来的、不是训练出来的"这一信任前提的可执行审计。

为什么值得

  • 发布体积：22.2GB → 基座约 8GB + 约 130MB 增量（zlib 后约 6MB）。
  • 可审计：如果重建的 chip 权重与发布 checkpoint 逐位一致，说明 chip 层没有被偷偷训练/修改。
  • 可组合：安装一个新"设备"= 重新编译 + 合并，不需要训练。

阻塞/风险

  • anti-sink 列（8×1024 bf16）来自设备相关的前向拟合，必须作为配方存下来（16 KiB）。
  • 没有锚定编译器 commit / torch 版本；重建实现必须与发布方逐位一致。
  • merge 全量峰值 44.7GB RAM；只重建 chip 层约 4–6GB 可行。
原型完成（本机实测，76.3s CPU，含负对照）：发布 checkpoint 的 chip 侧全部是编译器输出。
检查项结果
电路 stats（12 层 / 3753 dims / 164 heads / 47,532 units / slots 1806）✅ 与 chipformer.json 完全一致
code_dims / tau_dim / mu_dim / id_code_dims / tokenizer 偏移与特殊 token✅ 逐项一致
12 个 chip 层 × 14 个张量✅ 168/168 张量 BIT-EXACT
最终 norm 的 chip 维（2560:）✅ BIT-EXACT
chip token embedding 行（236,469 行，11.78M 非零）✅ BIT-EXACT
文本行的 chip 特征（248,070 行，18.67M 非零）✅ BIT-EXACT
证据：analysis/rebuild/report.json（verdict 全 True；含每个发布 chip 张量的 SHA-256，可直接作为安装器验证清单）。
负对照/敏感性：比较器能抓单 LSB 翻转与 -0.0；用错误 seed 2036 重建后 store 的 ffn_units 从 47,532 变 47,602，layer 5 的 MLP gate/up/down 出现 mismatch（正是 store hash 单元所在行），其余 11 层保持 bit-exact——审计有判别力且能定位。 编译器用源码 SHA-256 锚定（树哈希 47B113EE1928B1557FBE08AB128F0170），弥补了"没有 git commit"的缺口。
意义：4.54GB 的 chip 层（其中只有 1.29M 个非零值）可以 ~80 秒从编译器重建， 发布物可以缩成「基座 + 配置 + 编译器 + 少量 anti-sink 常量」；同时提供了一条"第三方可验证发布权重未经训练/篡改"的审计路径。
整模型审计（Qwen 侧，接续完成）：发布模型的 426 个 Qwen 侧张量全部可解释、0 个无法解释—— 338 个 = 基座 + 零填充/norm 重缩放（bit-exact，含 embed Qwen 块 636M 值 0 差异）；80 个 = 再加可推导的 mute 常数 bf16(-1024/√4608)=-15.0625； 8 个 = anti-sink（仅 8 个 full-attention 层的 k_proj：RoPE 0–63 维为 0、每 head |key|=16±0.016；共 8192 元素 / 6144 非零 / 16 KiB bf16，来自设备相关拟合）。 全部 138,752 个差异元素都只在第 2732 列（mu）。也就是说：整个 22.2GB checkpoint 中，无法从「基座 Qwen3.5-4B + 编译器 + 配置」推导的数据只有 16 KiB。 附加发现：在 CPU 上重跑 fit_anti_sink 与发布值 cosine ≥0.999995、但只有 64.95% 位相等（max diff 2.4e-4）——证明 anti-sink 依赖设备/数值栈，必须随配方存储。 证据：analysis/rebuild/base_report.json、docs/notes/stage3-a2-base-audit.md。

02B · 设备树：把算法编译成"外设"中等优先级

RV32 核占 11–12 层、约 1M 非零权重。一个专用组合电路（排序网络、CRC、正则匹配、日期/单位换算）可能只要 2–4 层、几千个非零权重。 于是"能力"可以像设备一样插拔：每个设备有自己的 token 族、ROM 和输出码。

问题回答
收益模型可以"安装"确定性能力而不训练；可验证、可回放、可审计。
成本每个设备都要：编译 → IR 验证 → bf16 精确性论证 → 与 Qwen 的 mute/tau 耦合处理 → merge。
判据一个真实小算法（如 CRC32）编译进 IR 后，层数 ≤4、非零权重 <10 万、token 成本低于"让 Qwen 自己算"。
风险层数/宽度预算线性膨胀；设备组合的交互难以证明；安全面变大（每个设备都是攻击面）。

03C · 不可关闭的监控器（In-weight monitor）依赖外部资源

作者 follow-up 声称：把线性探针 + 标志日志编译进权重，可捕获 91% 的谎言、零误报；困难提示下回复级 AUROC 0.77。 这比"CPU"更贴近 AI 安全：监控器住在权重里，模型无法通过 prompt 关掉它。

但"不可关闭"需要覆盖证明，而不是 demo：模型能否通过 tool 调用/桥接 tag 绕过？换提示、换语言、换多轮后 AUROC 是否稳定？ 探针本身是否可被模型"学会忽略"？我们建议的最小证伪清单：3 个模型 × 3 类提示 × 500 条标注样本 + 与外部监控器对比。

本机判断：方向有价值，但作者未发布完整权重/数据，无法独立复现；暂列为"评审级"而非"原型级"。

04D · 记忆盘：快照的边界（已实测）原型完成

我们把"记忆盘"从口号变成可测边界：快照里到底有什么、多大、绑定什么、能不能跨模型。

文件数逻辑快照大小同样内容 UTF-8 文本被触达 state 行
177 B30 B4
10723 B300 B40
1007,180 B3,000 B400
512（满）36,741 B15,360 B2,050 / 6,660（30.8%）

约 72 B/文件（含目录项、order、len、next 指针与内容行）；逻辑量约为原文的 2.4×。 512 文件的被触达 state 行只有 2,050 条（每文件 4 行），按 float64 稠密上界估算约 6.8 MB；满容量解析估计总状态约 0.24 MB。 文档/模型卡里"11–30 MB"是 CHIP-8 v1 store / 4B 满容量的口径，不是 RV-store v2 只存非零行的实测。

可移植性实验

  • 同 seed：10/10 读回成功（100%），恢复后可继续 put。
  • 换 seed（2036/2037/2038）：0/10（全部 not found，无错误内容）——哈希槽全变。
  • slot_bits 8（槽更少）：4/10 成功——布局一变，部分名字碰巧命中，不可依赖。
  • 绑定因子：hash seed、hash_bits/slot_bits、n_chunks/n_names、tokenizer 的 Qwen token id（不是字节）、布局常量（NMAX=6、LEN_BITS=3、CMAX=104、TPR=14）、store 协议记录、IR head 布局。
  • 正面结论：IR 快照不可跨 seed/编译/tokenizer 移植，但逻辑内容（名字+文本）可移植——导入时重新 put 成本很低（journal 迁移）。

长名字别名（真实风险）

  • A = "the locker code for the safe room in"
  • B = "the locker code for the safe in room"
  • 前 6 token 相同 + 长度相同 ⇒ 同一 key：put B 覆盖 A；get A 返回 B 的内容。
  • list 只打印前 6 token："the locker code for the safe"。
结论：快照不是"可移植的记忆文件"，而是绑定编译（hash seed / 布局 / tokenizer）的状态切片； 逻辑内容很小（512 文件 36.7KB，约 1.16× 文本信息量），物理状态是稠密 GDN 行（11–30MB 量级）。 产品化需要一个"记忆盘"格式：版本 + seed/布局元数据 + 迁移/校验 + 名字规范化。

05E · 自举 Qwenputer / in-weights Linux（量级边界）思想实验

把 Linux 跑进权重里需要多少？RV32 核 = 11 层 / 1.04M 非零权重 / ROM 256KB。 Linux 内核约 30MB 代码 → ROM 差约 100×；若按比例放大：数百层、数亿到数十亿非零权重，且每 token 成本线性增长。 在 44 层 / 11B 参数的 transformer 里，这超出预算 2–3 个数量级。

更现实的中间形态：把编译器的子集（词法/解析/代码生成的一小部分）编译进权重，模型调用它生成新固件—— 即"模型自己写设备"，但仍需人设计 ISA/ABI/验证器。自举（模型运行编译器生成自己的电路）在近期的 bf16/kernel 约束下不可行。

这条思想实验的价值：给"模型内计算机"画出清晰规模边界，避免把它误解为通用计算机。
